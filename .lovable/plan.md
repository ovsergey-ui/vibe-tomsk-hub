## Проблема

В `src/components/site/ChatWidget.tsx` оптимистично добавленное сообщение пользователя получает временный id `tmp-<timestamp>`. Поллинг затем берёт `lastId = messages[last].id` и шлёт его как `afterId`. Сервер не находит такой id в БД, считает курсор пустым и возвращает всю историю. В список добавляется реальная копия того же пользовательского сообщения (id отличается от `tmp-`), поэтому дедуп по id не срабатывает — получаем дубль. При повторных тиках поллинга может задвоиться и ответ ассистента.

## Исправление (одно место — `ChatWidget.tsx`)

1. При вычислении `afterId` для поллинга брать **последнее сообщение с реальным uuid**, игнорируя элементы с id, начинающимся на `tmp-`. Если реальных ещё нет — не передавать `afterId` (и пусть сервер вернёт всё).
2. При мердже новых сообщений из истории удалять временные оптимистичные элементы того же `role: "user"` с совпадающим `content`, заменяя их реальной записью из БД.
3. Не делать второй «full reload» (`if (!messages.length && !res.messages.length)`) — он лишний после правки выше и сам по себе может приводить к гонкам; начальная загрузка и так покрывается первым `load()` без `afterId`.

Никаких изменений в серверных функциях, БД и админ-панели не требуется.

## Проверка

- Открыть виджет, отправить сообщение → видно ровно одно «пузырь» пользователя, затем один ответ ассистента.
- Дождаться двух-трёх циклов поллинга → дублей не появляется.
- Перезайти на страницу (сессия из localStorage) → история подтягивается без дублей.
